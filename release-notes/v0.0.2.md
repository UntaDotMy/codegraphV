## codegraphV v0.0.2: the new name, one-step migration, faster indexing

codegraphV is a **full rewrite in Rust** of
[CodeGraph](https://github.com/colbymchenry/codegraph) by **Colby McHenry** (MIT). The design,
graph model, MCP tools, extractors and resolvers are his. This release renames the rewrite so it
never collides with the original, and makes it faster on big projects.

### Highlights

- **New name: codegraphV.** The command is `codegraphV`, the project folder `.codegraphV/`,
  the MCP server `codegraphV` with `codegraphV_*` tools, and the variables `CODEGRAPHV_*`. It
  can be installed next to the original codegraph without either one touching the other.
- **One-step move from the original:** `codegraphV migrate` rewires your agents, moves each
  project's `.codegraph/` index over without re-indexing, and removes the original (the npm
  package or v0.0.1's binary). `--dry-run` shows the plan first.
- **Coming from v0.0.1:** just run `codegraph upgrade`. It installs codegraphV and runs the
  migration for you. It then says `codegraph` was not updated; that is expected, because
  codegraphV replaced it.
- **Indexing a big repo is 44% faster than v0.0.1:** 30.8 s instead of 54.7 s on a 1878-file
  repo, with a byte-identical graph. It now uses every core.
- **CLI queries are fast again:** `codegraphV explore` answers in 37–53 ms. v0.0.1 synced the
  whole project before every CLI query, which cost up to about 900 ms on a large repo.
- **The Claude prompt hook works without PATH:** the hook now calls codegraphV by its full
  path, which fixes "codegraph: command not found" when Claude Code runs hooks in Git Bash.
- **No more leftover servers:** a server whose agent is gone exits within about 5 seconds,
  even if something still holds its input open.

### Fixes

- The `CODEGRAPHV_DIR` folder override now holds every per-project file, including the
  database (v0.0.1 still created `.codegraph/`).
- On Windows, the shared background server no longer keeps the agent's pipes open after the
  agent exits.

### Benchmark (Windows 11, Ryzen 5 2600, 6 cores / 12 threads)

| repo | files | Rust index | TypeScript index | Rust explore | TypeScript explore |
|---|---|---|---|---|---|
| serde_json | 69 | **1.1 s** | 4.1 s | **37 ms** | 1039 ms |
| tokio | 555 | **5.2 s** | 15.3 s | **48 ms** | 1175 ms |
| codegraph | 1878 | **30.9 s** | 51.0 s | **53 ms** | 1949 ms |

Both engines build identical graphs on every row. The full tables, including memory and
recall, are in the README and in `docs/benchmarks/rust-v0.0.2/`.

**What got worse:** indexing a large repo now peaks at about 2.1 GB of memory, against 1.1 GB
for v0.0.1 (TypeScript: 4.0 GB), because every core works at once. Set
`CODEGRAPHV_RESOLVE_WORKERS` and `CODEGRAPHV_PARSE_WORKERS` lower to use less.

### Install

```powershell
# Windows
irm https://raw.githubusercontent.com/UntaDotMy/codegraphV/rust-rewrite/install-rust.ps1 | iex
```

```bash
# macOS / Linux
curl -fsSL https://raw.githubusercontent.com/UntaDotMy/codegraphV/rust-rewrite/install-rust.sh | sh
```

Then run `codegraphV install`, or `codegraphV migrate` if you used the original codegraph.
In each new project, run `codegraphV init`.

### Known gaps

- The binary is about 74 MB.
- The browser viewer is a preview behind `CODEGRAPHV_UI=1`, and it lacks some of the
  original's views.
- There is no npm package and no JavaScript library API.
- The CLI answers from the index as it is, like the original's CLI. While an agent session
  runs, its server keeps the index current; otherwise run `codegraphV sync` after editing.

Every archive is listed in `SHA256SUMS`.
