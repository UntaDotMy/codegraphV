# codegraphV v0.0.13

### Highlights

- **An Intel Mac archive is back.** v0.0.12 shipped Windows and Linux only; GitHub's macOS runners were too busy to start the jobs. They run on the `macos-15-intel` label now, and this release publishes `codegraphV-v0.0.13-macos-x64.tar.gz` again. There is still no Apple Silicon archive: `install-rust.sh` stops there and prints the command to build from source.
- **A Rust project that uses `Option`, `Result`, `Mutex`, `RefCell` and friends no longer loses its links.** When a project declares a type of its own named `Option`, `Result`, `Vec`, `HashMap`, `Mutex` or `Pin`, the resolver used to read every use of that name as the project's type, so `guard.lock().unwrap()` and `map.get(..)` stopped linking to anything. A std reading is now kept beside the project's own type, per file, and a project type keeps links only where the file can actually see it. This matters most for Rust code: on this repository a similar gate had already dropped 12 false links.
- **Guard read-through.** A call through a `Mutex`, `RwLock` or `RefCell` now reaches the method of the value it holds, through `Arc`, `Rc`, `Box`, `Option` and `Result` wrappers, so `state.lock().unwrap().finish()` links to `finish`. A cell built around a wrapper keeps no payload type rather than guessing.
- **A glob-imported `Ok`, `Err` or `Some` is not the standard one.** `use crate::names::Outcome::*;` followed by `Ok(..)` now reads as that enum's variant, not `std::result::Ok`.
- **A type alias with a default parameter keeps its target.** `type A<M = ()> = T;` was invisible to both readers of the alias, so a binding typed by it, or a call on a receiver of `T`, linked nothing.
- **The Claude prompt hook no longer mistakes a short reply for a request.** "ok, go ahead" and "continue" are turn-taking, so nothing is injected; a one-word identifier still is.
- **`codegraphV cycles` reports cycles it used to miss.** It only looked at import statements, so two files that call or reference each other without importing one another were not a cycle. It now follows every cross-file link between symbols, as the original engine does, and lists a cycle once per link that closes it.
- **A git sync hook left by the original `codegraph` is now adopted, not duplicated.** A project that had run it kept its hook, and `codegraphV init --git-hooks` did not recognise it: it added a second block beside the first, so every commit ran both `codegraph sync` and `codegraphV sync`. The old block is now recognised and replaced in place. If a project already has two blocks from an earlier upgrade, running `codegraphV init . --git-hooks` on this version rewrites it to one.
- **A Rust type or function written inside a declarative macro is indexed.** `pin_project! { pub struct Timeout<T> { .. } }`, tokio's `cfg_rt!` and `cfg_io_util!` wrappers and `feature!` blocks all reach the parser as one opaque macro call, so everything declared inside them was missing from the index — and therefore from callers, impact and explore answers. The declaration is now read out of the macro body whenever the body parses as a run of items, which is decided by the grammar rather than by a list of macro names. On tokio 1.52.3 this takes the indexed type names from 464 to 547 and the file's missing declarations from 97 to 0. `macro_rules!` definitions, expression macros and macros inside a function body are untouched.

Coming from v0.0.12, run `codegraphV index` once per project to pick up the resolver changes, and once in each Rust project for the macro fix; projects without Rust need nothing.

### Fixes

- A std `Mutex`, `RwLock` or `RefCell` built by `::new` keeps the type it holds, so its accessor reads that type.
- `Some(x)`, `Ok(x)` and `Err(x)` keep the type of `x`, bare or under `Option::` / `Result::` / a std path. A variant imported from elsewhere in the crate is not the standard one and keeps no type.
- A cell built around a `Box`, `Rc` or `Arc` payload (`Mutex::new(Arc::new(..))`, directly or through a binding) keeps no payload type, so its `clone` no longer links to the payload's `clone`.
- A std sequence or map read through its std path (`std::collections::HashMap::new()`, `Vec::new()`) is read as std even when the project declares the same name.
- A std lock result is read as std, so a project `Result` alias does not hide it.
- A guard behind `Rc` or `Box` reads through to the value it holds.
- `install-rust.sh` refuses Apple Silicon Macs with a message naming the reason and the build-from-source command, instead of failing later with a download error. Its platform refusals have a test that stubs `uname`.
- A Rust item written inside a declarative macro is indexed: the body is unwrapped when the grammar reads it as a run of items, and re-parsed for the next nesting level. A file whose blanked form does not parse cleanly is walked as written.
- `scripts/rust-golden/extract.mjs` accepts a Rust file that only gains rows from an unwrapped macro body, and still fails on a lost oracle row or an addition in a file with no brace-form macro.

### Known gaps

These are measured and not fixed yet; each is in `audit/2026-11-03-overall/upstream-ledger.md`:

- **Rust: a `static` written inside `lazy_static!` or `thread_local!` is still not indexed.** Those bodies declare values in the macro's own syntax, not Rust declarations as written, so they are refused rather than guessed at. An item a macro *generates* (a name built from `$name`) is likewise not recovered.
- **Rust: a call through a `Pin` onto a type parameter still links nothing** (upstream #3315). `me.inner.as_mut().start_seek(pos)` on a `#[pin] inner: W` under `impl<W: AsyncWrite + AsyncSeek>` gives no edge. The bound reader that would answer it already exists for `T::method()`.
- **A glob the walk cannot resolve still reads as the standard variant.** A dependency's glob (`use parking_lot::*` then `Mutex::new`) still reads as std, which is correct; a glob into code the index cannot see does not.
- **A child's `use super::*` over a parent whose variant comes from an enum glob** still reads as std.
- **A project `Option` or `Result` type blocks the method route** for a call made on such a receiver in a file that cannot see the project type.
- **TypeScript: callback parameters, call results and type guards do not type the receiver** (upstream #3319, the largest gap in this batch). A JS/TS receiver is typed from a written annotation and from destructured call results only.
- **C#: an extension method's overload is not chosen by its arguments** (upstream #3313); PHP: the Eloquent factory list is not read (upstream #3314); Ruby: a class name is not scoped to its test suite (upstream #3316).
- **`sync` re-walks every package manifest** even when git shows none came or went (upstream #3317; about 150 ms on a large JavaScript project).

### Not measured

- **Parity for this change rests on one corpus.** The Rust macro recovery was measured on tokio 1.52.3 only. `scripts/rust-golden/extract.mjs` now accepts the recovery as a documented, one-directional divergence — a Rust file may gain rows the TypeScript reference lacks, never lose one — and both that corpus and this repository's own `crates/` are at full parity for everything else. No other Rust corpus and no agent A/B was run.
- **This release has no new timing table.** The changes add and remove links, list cycles, rewrite a git hook and re-parse only the files whose macros were unwrapped; none of them is on the indexing path for an ordinary file. No benchmark pass was run, so this release makes no speed claim either way.
- **Parity was checked per gate, not through `verify.mjs`.** `verify.mjs` runs every gate and then records a checkpoint; it stops at its first failing gate and one of them (`context`) still differs, so the checkpoint was not refreshed. The gates that pass on this release's code are recorded in the ledger by name: `graph` (8,755 answers), `context` (8,619), `watcher` (6,508), `sync` (468) and `query-paths` (1,630).
- `codegraphV cycles` output changed: a file set with more than one closing link is listed once per link, as the original engine lists it. If a script parsed the old one-entry-per-group output, it will see more entries.

### Upgrade

On Windows, Linux and Intel Macs:

```text
codegraphV upgrade
```

Then reconnect your agent, and run `codegraphV index` once in each Rust project.

**On an Apple Silicon Mac** there is no archive: build from a checkout of the `v0.0.13` tag with `cargo build --release --locked -p codegraph-cli`.
