# codegraphV v0.0.10

### Highlights

- `codegraphV install` now sets up nine more agents: IBM Bob, Factory Droid, Windsurf, Qwen Code, DeepSeek Harness, Grok Build, Kimi Code, Qoder CLI and Pi.
- `codegraphV init` on a project that is already indexed now syncs the changed files instead of rebuilding everything. A full index runs only when there is no index, the last one didn't finish, or an older engine built it. From there, background sync keeps the index current.
- When an index was built by an older engine, `sync`, `status` and the MCP server say so once and name `codegraphV index` as the fix.
- `codegraphV status` shows files parsed beside files found per language, and `--strict` exits non-zero when the index is incomplete or out of date.
- New commands and options: `codegraphV implementations <type>`, `files --format package`, `files --tests` / `--no-tests`, and `init --local-only`, which keeps `.codegraphV/` out of git.
- New frameworks and links: CodeIgniter 3 routes, Drupal services and hooks, Next.js proxy, MediatR handlers, Razor views calling their JavaScript, and Tauri frontends calling Rust commands.
- Better answers in C, C++, Objective-C, Python, Rust, Go, Swift, Java, Kotlin, C#, Ruby and JavaScript/TypeScript.

Re-index your projects (`codegraphV index`) to pick up the resolution changes.
Existing indexes stay readable until then.

### New Features

- Installer targets `bob`, `droid`, `windsurf`, `qwen`, `dsh`, `grok`, `kimi`, `qoder` and `pi`. Each writes where that agent reads and honors its home variable (`QWEN_HOME`, `GROK_HOME`, `KIMI_CODE_HOME`, `QODER_CONFIG_DIR`, `PI_CODING_AGENT_DIR`, `DSH_HOME`). Windsurf and DeepSeek Harness are global only.
- `CODEGRAPHV_SYNTH_MIN_INTERVAL_MS` limits how often live syncs rebuild the synthesized dynamic-dispatch links on very large projects.
- `status` recommends a re-index when `package.json` alone adds or drops a framework.
- `files` marks test files in `--json` output and groups files by their owning package.

### Fixes

- A worktree that borrows another checkout's index now says `Run "codegraphV init" in this worktree`, and tells an agent that the user can run it, instead of naming the retired `init -i`.
- Swift closures reach the overload that takes a function; Java overloads are chosen by their arguments, including lambdas and method references; Java and C# ancestor walks no longer depend on resolve order.
- Kotlin chains read through `StateFlow`, `LiveData`, `Lazy` and `Pair` holders; Kotlin Multiplatform imports reach `expect` or `actual` by source set.
- C# type-argument arity, keyword-typed receivers and extension methods decide what a name means.
- Ruby calls on a parameter take its class from the method's call sites.
- C and C++ member types follow object-like macro renames; Objective-C structs link the types their members use; Rust `#[cfg]` file-per-alternative modules resolve; Go interface satisfaction compares parameter and result types.
- Sparse checkouts skip files they leave out, and status reports a widened or narrowed checkout.
- A long-running server re-reads Cargo manifests when they change, instead of resolving by what they said before.

### Not included in this release

- Upstream's performance work for its Node engine (worker pools, regex and cache tuning, the compile cache) has no counterpart in the native engine and was not ported. No native profiling was done to look for similar hotspots.
- Reading C/C++ include directories from a compile database is not implemented natively.
- The open release-audit items (viewer packaging, SBOM/attestation, coverage, real-repository agent measurements, arm64 validation) are listed in `audit/2026-11-03-overall/upstream-ledger.md`.

### Upgrade

```text
codegraphV upgrade
```

Then reconnect your agent and run `codegraphV index` once in each project.
