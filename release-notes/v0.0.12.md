# codegraphV v0.0.12

### Highlights

- A search guard for Claude Code. `install` and `upgrade` add a hook to your global Claude Code settings. The hook turns away Grep, Glob and shell searches for an indexed symbol until codegraphV has been asked about it once. `CODEGRAPHV_GUARD=0` in Claude Code's environment turns it off.
- Answers about a file you edited since the last sync no longer show the wrong code. Before, `explore` and `node` cut the edited file at its old line numbers, so you could get another function's code under the name you asked for. Now they show the whole current file when it is small. When it is large, they leave the source out and name the call that returns it. `callers`, `callees` and `impact` say which files changed, because their line numbers may be off.
- A file that never finishes parsing no longer stops `init` or `sync`. Some broken TSX sent the parser into an endless loop. Each file now has a time limit (`CODEGRAPHV_PARSE_TIMEOUT_MS`), and a file that runs past it is skipped and listed as a parse error.
- `explore` now lists the blast radius of the symbols you name: how many callers each has, in which files, and which tests cover it, so your agent knows what to update before editing. Rust unit tests count as tests too, by their `#[test]`, `#[tokio::test]` or `#[rstest]` attribute, even when they sit in the same file as the code.
- C++ calls through a template parameter are now linked. In `template <typename Txn> class Mixin`, a call to `Txn::Put(…)` now leads to `Put` in each class the project passes as `Txn`, such as `new Mixin<WriteTxn>(…)`. Before, nothing linked that call. On abseil this adds 1,100 links, the same ones the original CodeGraph finds.
- New command: `codegraphV cycles` lists circular imports. It exits with status 1 when it finds any, so `codegraphV cycles || exit 1` works as a CI check.

### Fixes

- Running `install` from your home folder no longer writes a project setup into it, such as `~/AGENTS.md` or agent config files. A setup for one project (`--location local`) is now refused there. Global setups, `--refresh` and `migrate` still work from the home folder.
- Checking for changed files no longer locks git's index (`.git/index.lock`), so it can't make a `git commit` or `git add` you run at the same moment fail.
- How calls are linked no longer depends on the order files are processed in, and very long alias chains in TypeScript, Lua and Pascal no longer run out of stack. A C or C++ macro rename now applies the same way in every file that includes it.
- A `workspaces` entry pointing outside the project, such as `"../sibling"` in `package.json`, no longer turns that folder into a package. Before, an import of that package could be linked to an unrelated function of the same name inside the project.
- Edits to source that `codegraph.json` includes even though `.gitignore` excludes it are now picked up by `sync` and reported by `status`. Before, git never reported those files, so their changes were missed.
- The Claude prompt hook no longer adds unrelated symbols when your whole message is a short reply such as "continue" or "ok, go ahead".

### Measured

A fresh `codegraphV init`, median of 3 alternating runs, on one Windows 11 machine (6 cores, 12 threads). v0.0.11 is the released Windows archive; v0.0.12 is the same archive built by the release workflow from this release's code:

| Project | Files | v0.0.11 | v0.0.12 |
|---|---:|---:|---:|
| codegraphV (Rust, TypeScript) | 2,053 | 39.0 s | 39.8 s |
| abseil (C++) | 811 | 11.4 s | 11.7 s |
| fmt (C++) | 69 | 4.6 s | 4.7 s |
| express (JavaScript) | 149 | 1.2 s | 1.2 s |
| gin (Go) | 110 | 1.3 s | 1.4 s |
| MediatR (C#) | 166 | 1.2 s | 1.2 s |

- **Indexing is within 3% of v0.0.11**, and peak memory within 2%: about 1,500 MB while indexing codegraphV, against about 1,470 MB. The C++ template links cost about 0.3 s on abseil. Apart from those new links, the fmt and abseil indexes are identical to v0.0.11's.
- **`explore` adds the blast radius.** The median of the twelve test queries takes 60 ms, against 57 ms, and the answers are about 8% longer. The slowest case is a query naming three heavily used symbols: 124 ms, against 97 ms. With that section removed, all twelve answers are byte for byte the same as v0.0.11's.
- **`sync` is slower on large C++ projects.** After editing one header, `sync` takes 5.8 s on abseil, against 4.7 s, and 2.4 s on fmt, against 2.0 s. During `sync` the linking passes run one at a time, so the new template pass's ~1 s adds in full; during `init` it runs beside the others. Projects without C++ code are not affected.
- **`impact` and `callers` now check every file they list for changes on disk**, on all cores at once. `impact CodeGraph` names 817 files and takes 534 ms, against 518 ms. `callers Node` takes 151 ms, against 147 ms (median of nine runs; v0.0.11 timed against itself differs by about 1%). Before the threaded check, `impact` was about 12% slower.

### Not included in this release

- An Apple Silicon (arm64) macOS archive, for the same reason as in v0.0.11: GitHub's Apple Silicon build machines are still too busy to run this repository's release jobs. On an Apple Silicon Mac, `codegraphV upgrade` stops with a download error and leaves your installed version in place. To get v0.0.12 there, build it from a checkout of the `v0.0.12` tag with `cargo build --release --locked -p codegraph-cli`.

### Upgrade

On Windows, Linux and Intel Macs:

```text
codegraphV upgrade
```

Then reconnect your agent. There is nothing to re-index unless one of the linking fixes above applies to your project; then run `codegraphV index` once there.

**If you ran `codegraphV install` from your home folder with v0.0.11 or earlier:** it may have left a codegraphV block in `~/AGENTS.md`. v0.0.12 will not remove it, because it no longer touches project files in the home folder. To clean up, delete the lines from `<!-- CODEGRAPHV_START -->` to `<!-- CODEGRAPHV_END -->` in that file, markers included.

**If you used the earlier Python search guard:** remove `~/.claude/hooks/codegraphv_guard.py` and its entry under `hooks` in `~/.claude/settings.json`. The new guard is built in, so keeping both runs each check twice.
