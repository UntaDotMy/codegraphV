## codegraphV v0.0.8: calls link to the right code in more languages, and installs and migrations fail safe

codegraphV is a **full rewrite in Rust** of
[CodeGraph](https://github.com/colbymchenry/codegraph) by **Colby McHenry** (MIT). The design,
graph model, MCP tools, extractors and resolvers are his. This release brings in the original's
latest resolver, security and reliability fixes, updates the bundled database engine, and makes
the Windows installer and `codegraphV migrate` safer when something goes wrong halfway.

### Better call links

Re-index a project after upgrading to get these (see Upgrade).

- **Go:** a method called on a variable that holds what a call returns or a conversion, like
  `r := newRing()` then `r.Reset()`, links to that method of the returned type. A value of a type
  from outside your project links to nothing instead of to a project method that shares the name.
- **Java:** a call resolves on the type its receiver is declared with in more cases: a field of an
  outer class read inside an inner or anonymous class, `Outer.this.field`, a chain of fields, a
  local declared with type arguments, a for-each variable, a type written with its package. A type
  from a library, like `Parcel` or `java.util.List`, no longer links to a same-named method of
  yours.
- **Kotlin:** a call through a property, a constructor property or a chain, like
  `engine.pump.drain()` or `Mode.ON.next()`, links to the method of the declared type. A library
  type gets no guess unless your project extends it; an imported class wins when two packages
  declare the same name; a `private` property or class stays in its file; a `fun interface` is
  indexed as an interface.
- **Rust:** calls through a module path (`crate::`, `super::`), a `use` that renames, a `use`
  inside a function or block, and a `use` of an enum variant link to the item the path names. A
  parameter, closure or local that shares a function's name no longer links to that function.
- **Scala:** `Outer.Inner(...)` links to the case class or object it builds.
- **Python, Scala, Java:** a standard-library method called on a value whose type is unseen, like
  `options.setdefault(...)`, no longer links to an unrelated project method of the same name.
- **Java, Scala, Python, TypeScript, JavaScript:** a call on the caller's own class, or through
  `self` or `this`, links to that class's method or the one it inherits, not a same-named method
  of another class declared closer in the file.
- **All languages:** a method that hands its call on to another object's method of the same name
  no longer looks recursive.
- **C and C++:** a function-pointer table's handler links only to C and C++ functions. An `#if`
  group that is not made of whole statements no longer turns into functions named `if`.
- **JavaScript and TypeScript:** a `tsconfig.json` path alias with text on both sides of its `*`
  no longer matches an import that leaves nothing for the `*`.
- **React, Svelte, Astro, Vue:** a component used without an import prefers the definition in the
  using file's own folder, compared folder by folder.
- **Duplicated code:** when a project keeps copies of the same code in several folders, a call
  links to the copy in the caller's own folder. Ties are broken the same way on every machine,
  whatever its language settings.

### Indexing and status

- A full index no longer warns about a partial index for a video named `.ts`, and a file you
  deleted but git still lists is skipped instead of reported as unreadable.
- A program that uses codegraphV as a library and indexes a project it has indexed before keeps
  every symbol findable by the words in its name.
- `codegraphV status` reports uncommitted edits in a project that sits in a folder of its git
  repository, and says which frameworks changed since the last full index.
- A long-running session notices a framework that arrives or goes while it runs.
- `query`, `explore`, `node`, `callers`, `callees`, `impact`, `context`, `files`, `status`,
  `affected` and the prompt hook only read the index: they no longer make a running
  `codegraphV index` fail with "database is locked", and they say when a rebuild is running.

### Folders and Windows

- A sensitive folder such as `~/.ssh`, `~/.config`, `/etc` or `C:\Windows` is refused as a project
  however it is reached: through a link or junction, a differently capitalized name, or a `\\?\`
  path. The MCP server no longer uses one as a session's default project.
- A project at the root of a Windows drive, like a mapped network drive, now indexes.
- A git worktree inside your main checkout is recognized however Windows spells its path.
- The Windows installer no longer stops with "(403) Forbidden" when GitHub's hourly limit for
  anonymous requests is used up.
- The Windows installer copies the new executable in full before it moves the working one, and
  puts the working one back if activating the new one fails.

### Migration

- `codegraphV migrate` removes the original index only after the new `.codegraphV/` is a healthy,
  completed index. An empty, damaged or unfinished one keeps both folders and prints how to
  recover.
- If migrating the agent configuration or the index fails, the original program and settings stay
  installed and the command exits with an error. Each retry saves its configuration backups in a
  separate folder, so a second try cannot overwrite the first backup.

### Reliability and speed

- The bundled SQLite is now 3.51.3, which includes the fix for a rare corruption race between
  simultaneous writes and checkpoints in WAL mode. No corruption was observed; this removes a
  known risk. The index format is unchanged.
- Plain symbol queries no longer build a map of every indexed path first.
- An exact line range returns its source without repeating dependency summaries. On this
  repository's own index, selected requests were about 1.9 times faster and their responses 13%
  to 53% smaller (warm timings of one machine, not a whole agent session).
- When a directory-qualified path in an explore query is not in the index, the answer says so
  before showing other matches.

### Upgrade

```bash
codegraphV upgrade
```

Existing `.codegraphV/` indexes keep working; the index format is unchanged. To get the new call
links in a project, run `codegraphV index` in it. Re-index Go, Java, Kotlin, Rust, Scala, Python,
C, C++, TypeScript, JavaScript, React, Svelte, Astro and Vue projects.

### Install

```powershell
# Windows
irm https://raw.githubusercontent.com/UntaDotMy/codegraphV/rust-rewrite/install-rust.ps1 | iex
```

```bash
# macOS / Linux
curl -fsSL https://raw.githubusercontent.com/UntaDotMy/codegraphV/rust-rewrite/install-rust.sh | sh
```

Then run `codegraphV install`, or `codegraphV migrate` if you used the original codegraph.
In each new project, run `codegraphV init`.

### Known gaps

- The browser viewer is a preview behind `CODEGRAPHV_UI=1`, and it lacks some of the
  original's views.
- There is no npm package and no JavaScript library API.
- The CLI answers from the index as it is, like the original's CLI. While an agent session
  runs, its server keeps the index current; otherwise run `codegraphV sync` after editing.
- Indexing time with the new resolution rules has not been measured against v0.0.7, and
  end-to-end token savings for a whole agent session have not been measured.
- The new call links were compared with the original on small fixture projects (74 of 74
  identical), not on large real repositories.

Every archive is listed in `SHA256SUMS`.
