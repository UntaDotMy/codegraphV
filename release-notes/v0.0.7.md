## codegraphV v0.0.7: explore answers stay on the file you named, and a long line is no longer a dead end

codegraphV is a **full rewrite in Rust** of
[CodeGraph](https://github.com/colbymchenry/codegraph) by **Colby McHenry** (MIT). The design,
graph model, MCP tools, extractors and resolvers are his. This release fixes three ways an
explore answer could point at the wrong code or refuse to move forward, makes searches several
times faster, and keeps every response inside the size it advertises.

### Fixes

- **Naming a file now keeps the answer on that file.** When two files defined the same symbol,
  naming one of them in the query could still show the other file's function, or trace the flow
  through it. Definitions and flow endpoints now prefer the file you named, so the source you
  are shown is the source you asked for. Helper calls in other files still resolve, so the flow
  does not stop at the first hop.
- **Continuing an answered response always moves forward.** A continuation could spend its whole
  page on the same leading lines and come back with nothing new, repeating forever. It now
  returns a range that starts past what you already have.
- **An explicit line range is returned even if that source was shown earlier.** Asking for
  `file.rs:40-60` is now treated as a deliberate reread instead of "already shown in this
  session".
- **A source line too long to fit is now retrievable.** It is returned in pages of Unicode
  characters, each page carrying a content hash, so an edit in between is reported instead of
  silently joining two versions of the line. Lines that do not fit no longer hide the
  definitions after them.
- **Continuation works for paths with spaces in them.** A whole indexed path is matched before
  the query is split into words, so the returned continuation query can be used as-is.
- **Edited files no longer accumulate stale display history.** Old content versions for that
  file are released, and the edited source is shown again.

### Performance

- **Search is about 3 to 4.5 times faster on common words** while returning the same rows in
  the same order with the same scores (measured on this repository's own index).
- **Explore responses stay within their advertised size.** Metadata, flow paths and the
  continuation footer all fit inside the character budget now, so an agent host is less likely
  to truncate a response or push it out of context. A flow path is still shown whole, never cut
  mid-hop.

### Upgrade

```bash
codegraphV upgrade
```

No re-index is needed. Existing `.codegraphV/` indexes keep working; there is no index
migration. Agents should reload their MCP server configuration to pick up the corrected tool
descriptions.

### Install

```powershell
# Windows
irm https://raw.githubusercontent.com/UntaDotMy/codegraphV/rust-rewrite/install-rust.ps1 | iex
```

```bash
# macOS / Linux
curl -fsSL https://raw.githubusercontent.com/UntaDotMy/codegraphV/rust-rewrite/install-rust.sh | sh
```

Then run `codegraphV install`, or `codegraphV migrate` if you used the original codegraph.
In each new project, run `codegraphV init`.

### Known gaps

- The binary is about 74 MB.
- The browser viewer is a preview behind `CODEGRAPHV_UI=1`, and it lacks some of the
  original's views.
- There is no npm package and no JavaScript library API.
- The CLI answers from the index as it is, like the original's CLI. While an agent session
  runs, its server keeps the index current; otherwise run `codegraphV sync` after editing.
- Query-level timings above were measured directly against the index. End-to-end token savings
  for a whole agent session have not been measured.

Every archive is listed in `SHA256SUMS`.
