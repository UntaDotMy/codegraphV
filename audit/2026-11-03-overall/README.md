Closures, macros and generated declarations require an AST-based inventory; the reference-language inventory is also lexical and incomplete for methods/arrow functions. ## What happens when someone installs and uses it

| Stage | Actual native behavior | Persistent effects and caveats |
|---|---|---|
| Bootstrap with `install-rust.ps1` | Resolves a release, downloads ZIP and SHA256SUMS, checks hash, stages binary, renames previous binary aside, swaps and attempts rollback if swap fails. | Default `%LOCALAPPDATA%/codegraphV/bin`; adds user PATH and prepends current process PATH. Does not ordinarily configure agents or index projects. The legacy environment-variable path can run `migrate --yes`. |
| Bootstrap with `install-rust.sh` | Detects Linux/macOS and CPU, downloads archive/checksums, stages then renames executable. | Default `~/.local/bin`; prints PATH advice rather than editing shell profiles. Linux arm64 is explicitly refused. Legacy mode runs migration and suppresses its failure with `|| true`. |
| Bare executable | Interactive stdin starts agent setup; noninteractive stdin prints help. | Merely running the binary does not index in the noninteractive case. |
| `install` | Global scope by default; auto-detects target config paths/parents, falling back to Claude if none found; asks before configuration unless `--yes` or refresh. | Writes MCP entries using the absolute current executable. Does not index unless `--init` is passed. |
| Claude integration | Writes MCP entry, fenced guidance, optional tool allow-list and prompt hook. `--yes` enables the prompt hook; `--no-permissions` controls permission, not the hook. | Hook reads `{prompt,cwd}` and returns graph context for structural/code-related prompts. Existing hook choice survives refresh, but existing permission choice currently does not. |
| `init` / `index` | Both dispatch to initialization/open plus full `index_all`, with root checks and cancellation handling. | Creates `.codegraphV/codegraph.db` and internal `.gitignore`; stores extraction/version metadata. Does not call Git hook installation. `index --quiet` is parsed but discarded in the shared arm. |
| MCP connection | `serve --mcp` connects to native daemon where applicable; initialization is lazy. Tools open indexed projects, catch up and watch according to configuration. | Background watcher/daemon lifetime belongs to connected runtime, not a permanently installed OS service. Separate project idle release exists. Update availability checks can contact GitHub; no telemetry is claimed by README. |
| Prompt hook | Ignores empty, task-notification, agent and cross-session messages; detects indexed project; opens read-only; avoids active rebuild; renders context or symbol hints. | Most failures produce no context. Empty segment vocabulary may be healed through a separate writer. Output is capped after rendering; no native wall-clock deadline is imposed. Disable with `CODEGRAPHV_NO_PROMPT_HOOK=1` or `CODEGRAPHV_PROMPT_HOOK=0`. |
| Git sync hooks | Library supports `post-commit`, `post-merge`, `post-checkout`, preserving marker-owned blocks and multiple projects. | No production CLI/core caller wires installation/removal. Their generated command uses `codegraphV` from PATH, unlike the absolute Claude hook path. Do not tell users these are automatically installed. |
| Upgrade | Downloads installer from mutable `rust-rewrite` branch, pins requested binary release, verifies installed version, checks PATH precedence, runs `install --refresh` unless disabled. | Refresh defaults to global scope. Existing processes use handoff machinery. Reindex advice currently offers incremental sync as well as full index even though unchanged source may require re-extraction. |
| Migration | Plans original agent entries, indexes and program/state cleanup; supports dry-run, backup and retry. | Can remove the original install/state after migration. Multi-file operations are not one transaction. Do not treat it as a harmless alias rename. |
| `uninstall` | Removes chosen target entries at chosen scope. Global uninstall also removes CLI unless `--keep-cli`. | Other scope configurations and project indexes are not recursively discovered/removed. Selected-target global uninstall can leave another configured target pointing at a removed CLI. |
| `uninit` | Removes selected project index after confirmation or force. | Does not stop runtime or remove Git hook blocks through the hook helper; does not remove agent config. Help says generated integration files are removed, which is broader than this implementation. |

## Native findings and improvement backlog

### Installer, hooks and upgrades

**A01 — P1, reproduced: refresh overrides the permission opt-out.** `crates/codegraph-cli/src/main.rs:870` always passes `auto_allow: !no_permissions`; `crates/codegraph-installer/src/lib.rs:426` rewrites the permission list. Install Claude locally with `--yes --no-permissions`, then run `install --target claude --location local --refresh`: the absent permission becomes `mcp__codegraphV__*`. Upgrade invokes this refresh too. Implement a preserve/enable/disable permission choice, default preserve on refresh. Preserve narrower manually configured permissions rather than replacing them with wildcard access. Acceptance: no permission before means none after refresh; restrictive entries remain restrictive; explicit enable/disable still works; cover automatic upgrade refresh.

**A02 — P1, reproduced: hook ownership uses substring matching.** `crates/codegraph-installer/src/lib.rs:563` accepts any command containing a known hook form. A user-owned `Stop` command `echo codegraphV prompt-hook` is deleted by local Claude uninstall; refresh can similarly rewrite lookalikes in UserPromptSubmit. Parse an exact recognized command/argument form or use explicit managed identity. Acceptance: comments, `echo`, wrapper strings, suffixed names and unrelated compound commands survive; actual old and current managed forms are removed/migrated.

**A03 — P2, reproduced: shared guidance has no remaining-consumer check.** `instructions_path` maps local Codex and OpenCode to the same `AGENTS.md`; `apply_as` unconditionally removes its fenced block when either target uninstalls. Installing both then uninstalling Codex leaves OpenCode configured but deletes the guidance file. Retain shared guidance while another configured target needs it. Test both removal orders, existing user content and repeated uninstall.

**A04 — P1, source-confirmed: the generated shell hook is not safe for all valid executable paths or current Windows fallback shells.** `prompt_hook_command` at installer `lib.rs:559` surrounds a slash-normalized path with double quotes without escaping shell metacharacters. `$` and backticks can be expanded by a shell; double quotes inside POSIX path names are also not handled. The same quoted command lacks PowerShell's invocation operator. Current Claude documentation supports direct exec form (`command` executable plus `args` array) and PowerShell fallback when Git Bash is absent. Prefer exec form with a stated supported-host version, or correct per-shell quoting for legacy clients. Test spaces, apostrophes, dollar signs, backticks, Unicode and Windows without Git Bash. This is source-confirmed compatibility/escaping exposure, not a demonstrated arbitrary-code exploit. [Claude hook command semantics](https://code.claude.com/docs/en/hooks#command-hook-fields).

**A05 — P2, source-confirmed: Git hook support is disconnected from setup/cleanup.** `crates/codegraph-sync/src/git_hooks.rs:214` and `:277` have no production callers in CLI/core. Wire an explicitly chosen policy into installation/init and cleanup, or document them as library-only. Acceptance: a real temporary Git repo gets only the requested hooks; existing non-shell hooks, custom hooksPath, linked worktrees, subprojects and user content survive; uninit removes only owned blocks. Validate background sync without a convenient development PATH.

**A06 — P2, source-confirmed: uninit's help overpromises cleanup and can contend with live runtime.** `main.rs:86` describes generated integration cleanup, but `:444` only calls `directory::remove_directory`; no daemon stop/lock coordination or hook removal occurs there. Align help and lifecycle behavior. Acceptance: active watcher/daemon plus uninit is tested on Windows and POSIX; no unexpected index resurrection, confusing partial deletion or stale managed hook remains. Existing active-runtime failure behavior is a validation target, not reproduced here.

**A07 — P2, source-confirmed: uninstalling one global target also removes the shared executable.** `main.rs:933` checks scope and `keep_cli`, not remaining configured consumers. The current prompt mentions configuration removal, not binary deletion. Keep the CLI while other targets depend on it, or clearly preview and require the intended all-target removal policy. Test two global targets, one local target, and `--target none`; verify retained entries remain runnable.

**A08 — P2, source-confirmed limitation: setup/migration changes are not transactional across files or targets.** Installer `lib.rs:489` commits sequentially after per-target planning; CLI iterates targets. A late I/O failure leaves earlier files changed. Introduce an operation plan, durable backups and rollback/recovery journal, including uninstall. Acceptance: inject failure at each write/delete, preserve unrelated content, rerun safely; race two installers and an external settings edit. Per-file atomic rename is already present and should be retained.

**A09 — P2, source-confirmed: POSIX installer has a fixed staging filename and fails before API fallback on some redirect errors.** `install-rust.sh` uses `$dir/.codegraphV.new`; concurrent installers can interfere. Under `set -e`, a failed curl in the `version=$(curl ... | sed ...)` pipeline depends on shell pipeline semantics; do not assume intended fallback works on every error. Use a unique stage plus install lock and explicitly handled network failures. Test concurrent versions, offline/403 redirect, wget-only host and interrupted rename. The fixed filename is confirmed; fallback failure is a test target.

**A10 — P2, source-confirmed: prerelease SemVer ordering is lexical.** `crates/codegraph-installer/src/upgrade.rs:80` compares full prerelease strings with `cmp`, so `rc.10` sorts below `rc.2`. Parse dot components and compare numeric identifiers numerically, with strict release-tag validation separated from display parsing. Tests: SemVer precedence chain, numeric/text components, build metadata, malformed/trailing input. [SemVer precedence specification](https://semver.org/#spec-item-11).

**A11 — P2, source-confirmed: upgrade refresh covers global defaults, not all existing local installs.** `crates/codegraph-cli/src/upgrade.rs:160` runs only `install --refresh`. Local instructions in other repositories are not refreshed. Define scope explicitly; optionally record managed installs or refresh the current project's existing entries. Do not scan/rewrite arbitrary projects without a product policy. Test local-only and global+local configurations.

**A12 — P2, source-confirmed: prompt hook has output limits but no work deadline or stdin size cap.** `crates/codegraph-cli/src/prompt_hook.rs:run/frontload_project` reads all stdin and renders before capping output. The installed hook omits `timeout`. Add bounded input and a short configurable budget with fail-open behavior; measure cold and busy-index p95. Current Claude docs say UserPromptSubmit blocks processing and defaults to a 30-second command timeout; that is a host fallback, not a good latency target. [Hook timeouts](https://code.claude.com/docs/en/hooks#userpromptsubmit).

**A13 — P2, source-confirmed: no noninteractive hook opt-out flag in install.** `--yes` implies prompt hook on, and `--no-permissions` does not disable it. Add an explicit preserve/on/off hook option or clearly document the kill switch and prompt implication. Test fresh install, refresh and migration separately. Do not conflate permission choice with context-injection choice.

**A14 — P2, source-confirmed: reindex advisory can suggest insufficient work.** Installer `upgrade.rs:151` offers `sync` to obtain extraction improvements, but incremental sync does not imply re-extracting every unchanged file. Align advice with extraction epoch and actual invalidation behavior. Test upgrading an index whose source bytes did not change but parser output should change; require a correct rebuild recommendation. The repository's v0.0.9 notes already correctly request full index for affected component projects.

### CLI, graph, MCP and viewer

**A15 — P1, source-confirmed and upstream pending: impact has no total-size budget.** `crates/codegraph-graph/src/traversal.rs:304` accumulates nodes/edges with depth only; a shallow high-fanout graph can still be enormous. Port upstream `cc863616` including explicit truncation metadata through CLI/MCP/viewer. Bound work while reading adjacency, not just serialized output. Acceptance: dense/cyclic and container-heavy graphs remain bounded, report incompleteness and retain valid endpoints.

**A16 — P2, source-confirmed: CLI glob matching is unanchored.** `crates/codegraph-cli/src/wire.rs:glob` returns a regex without path-boundary/end anchors. Patterns can match a substring of another filename. Port upstream `60b0d7a9` and its affected-filter tests; clarify recursive `**/`, folder-boundary and whole-name semantics. Keep files and affected filtering consistent. This is direct source evidence, not a runtime repro in this pass.

**A17 — P2, source-confirmed: query limits are normalized inconsistently.** `main.rs:507` fetches at most `limit.clamp(1,10000)+1` but warnings and `.take(limit)` use the original value. For requested limits above 10,000, a capped response can appear complete and may include the sentinel row. Normalize once and expose an effective limit/truncated flag. Test 0, 1, 10,000, 10,001 and very large inputs with more matching symbols than the cap.

**A18 — P3, source-confirmed: accepted flags have no effect.** The combined Init/Index match arm discards init `yes`/hidden `index` and index `quiet`. Some may be intentional compatibility flags, but quiet currently still prints JSON. Implement documented semantics or reject/deprecate inert flags. Verify CLI help and output/exit behavior with snapshots and process-level assertions.

**A19 — P1, source-confirmed hardening gap: protocol input queues are unbounded.** `crates/codegraph-mcp/src/session.rs:164` uses an unbounded channel and `reader.lines()` without a line cap. Daemon `:322` also uses an unbounded event channel; its authenticated reader does cap an individual request at 1 MiB. Add consistent frame caps and bounded queues/backpressure; cap unauthenticated connection threads if needed. Test oversized lines, floods while one expensive query runs, disconnect and subsequent normal client health. No network exposure beyond the current local transport is asserted.

**A20 — P2, source-confirmed architecture risk: one slow daemon query blocks other clients.** `daemon.rs:397` processes a client's request synchronously in the shared event loop; session notifications are ignored except roots changes. Add cancellation/work budgets and demonstrate fairness before adding complex concurrency. Test one broad query plus another client's ping, stop and cheap lookup. Avoid reintroducing multiple writers or unsafe shared SQLite ownership.

**A21 — P2, validation gap: current host/protocol matrix is not established.** `session.rs` always reports `2024-11-05`; it may legitimately offer an older supported version, so this alone is not a protocol defect. Test supported-version negotiation, initialization ordering, roots notifications, malformed requests, stdout closure, cancellation and reconnect with actual supported host versions. Keep recoverable misses success-shaped. [MCP lifecycle requirements](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle).

**A22 — P2, source-confirmed packaging gap, intentional preview: release archives omit viewer assets.** `.github/workflows/rust-release.yml` packages only binary, LICENSE and README. `crates/codegraph-ui-server/src/server.rs:23` searches for viewer assets externally and can fall back to the build checkout path. Clean-machine `CODEGRAPHV_UI=1` therefore needs separately supplied assets. Keep preview disclosure explicit; before launch, package assets/grammars, remove build-machine dependence, compare API views and run browser smoke from unpacked archives. Do not label the intentionally gated preview a generally available broken feature.

### Release, testing, security and maintainability

**A23 — P1, source-confirmed validation gap: no native pull-request CI trigger.** The only native workflow runs on `rust-rewrite` pushes, `v0.*` tags and manual dispatch. Add read-only PR testing on all three OSes and required checks before merge. Release publication must remain tag/manual-only. Current post-push tests are useful but do not protect review-time changes.

**A24 — P2, source-confirmed improvement: native releases lack build provenance attestations.** The native workflow creates checksums but has no attestation step; actions and Rust stable are mutable references. Add provenance, pin toolchain and actions appropriately, publish SBOM/license inventory and verify release assets after download. Checksums prove archive consistency with the downloaded manifest, not independent origin authenticity. Upstream's original release pipeline already includes attestation machinery. [GitHub attestation guidance](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations).

**A25 — P2, source-confirmed reproducibility gap: upgrade script is branch-pinned, not release-pinned.** `installer_url` uses `rust-rewrite` even when installing an older explicit binary tag. Fetch a validated script from the selected tag/commit or embed the installer logic with a clear compatibility contract. Acceptance: a pinned release produces the same installer behavior after branch updates; rollback installs remain usable. Account for legacy release tags lacking scripts.

**A26 — P2, source-confirmed governance gap: broad parity checkpoint is stale.** `check-upstream.mjs` exits 1 for changed files against `c8a80149`; its notes still say native CLI/MCP/installer replacement is pending even though those exist. This means "review required", not proof that all listed files are defective. Replace blanket state with per-domain pinned source/native fingerprints and regression gates; advance only after successful verification. Preserve the narrower v0.0.9 ledger.

**A27 — P2, validation gap: per-function coverage and cross-platform completeness are unknown.** No claim of manual review of all 7,349 declarations is justified. Add Rust-aware symbol indexing, source-to-test mapping, line/branch coverage, fuzz targets for parsers/config editors/protocols, and an explicit reviewed/needs-review ledger. Real Linux/macOS watcher delivery and OS-specific install behavior need recorded evidence, not only Windows scheduler-vector parity. The fresh workspace run is not a replacement for those gates.

**A28 — P2, validation gap: performance claims need current workload evidence.** Existing repo benchmarks and v0.0.9 synthetic session measurements are useful but not this pass's fresh agent A/B. Re-measure small/medium/large real repos, cold/warm startup, index/sync memory, query p50/p95, result sufficiency and total session cost. Validate session-history memory growth and synthesis memory on generated sources. Avoid shrinking answers merely to improve byte counts.

**A29 — P3, source-confirmed: formatting baseline fails.** `cargo fmt --all -- --check` produces diffs. Establish a formatter version and separate mechanical formatting from functional ports; then gate future touched code. Do not mix a workspace-wide reformat into correctness fixes.

**A30 — P2, source-confirmed documentation/maintenance drift.** Root guidance still mixes the original npm release process, old agent count/tool names and old explore budgets with native behavior. The reference `src` checkout is not the live upstream oracle. Scope native vs reference docs and scripts explicitly; retire or guard the original publishing workflow in this fork. Keep unpublished viewer changes separated. Acceptance: an agent can identify the correct build, release, parity oracle and supported commands without contradictory instructions.

**A31 — P3, intentional platform gap: no native Linux arm64 or Windows arm64 release artifact.** Native build matrix has Windows x64, Linux x64 and both macOS architectures; shell installer refuses Linux arm64 and PowerShell chooses x64. Add only with real install/run tests and declared glibc/CPU requirements; do not infer Windows ARM native support from x64 emulation.

**A32 — P2, validation gap: dependency/native-FFI security is not certified.** SQLite 3.51.3 update is already present; do not reopen that as an unported old fix. Run current RustSec/dependency/license checks against Cargo.lock, plus retained Node/site lockfiles and vendored grammar/PCRE/Wasmtime code; triage reachability and platform applicability. No fresh CVE database scan or fuzz campaign was performed here, and no new CVE is asserted. Current build emits linker warnings around tree-sitter/Wasmtime CRT imports; preserve logs and validate the shipped static-CRT binary on clean Windows without development runtimes.

**A33 — P1, reproduced: marker examples inside Markdown fences are mistaken for owned instructions.** `markers.rs:29` recognizes standalone marker lines without Markdown fence awareness. Installing into an AGENTS.md containing a fenced example overwrites the example and puts real guidance inside the fence. Ignore markers inside backtick/tilde fences; refuse ambiguous/nested ownership rather than deleting user text. See [preservation-plan.md](preservation-plan.md) for required cases.

**A34 — P2, reproduced: exact instruction-file round trips are incomplete.** Across Claude, Codex, OpenCode and Gemini, ordinary LF/CRLF files round-trip, but uninstall adds a final newline to an original file without one; whitespace-only originals are replaced on install and deleted on uninstall. Preserve original file existence and bytes outside owned additions. Do not restore a whole stale backup over edits the user made after installation.

**A35 — P1, source plus current-host documentation: adding local Claude guidance can shadow existing AGENTS.md.** The installer creates `.claude/CLAUDE.md`. Current Claude documentation says a project CLAUDE.md, including that location, prevents default direct AGENTS.md loading. Thus preserving the file on disk alone does not preserve its effect. Choose host/version-aware placement or a tested explicit import that retains prior instructions without changing global host preferences. This host behavior was researched, not executed in a live Claude session. [Claude instruction loading](https://code.claude.com/docs/en/memory#when-claude-code-reads-agentsmd).
